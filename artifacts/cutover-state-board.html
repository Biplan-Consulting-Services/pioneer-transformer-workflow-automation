What is decided

6 · settled 2026-09-08 → 09

Each decision is recorded with what it removed, because two items on the previous plan were not merely unnecessary — one of them would have broken the final run.

The transfer flow runs once more, then is deleted

Not made create-only, not kept as maintenance. “I want it to be rerunable so that I can re-upload the data on the cutoff date. After that I'm removing the flow — it will never be used again.”

  • KilledCreate-only. The final run's entire job is to update the 1,117 existing rows with staff's last edits. Create-only guts that branch — it would have created new rows and silently skipped every update, defeating the sync it was meant to protect.
  • KilledR7, removing the BO mapping and the 5 Order companion writes. That only matters if a future run could overwrite SharePoint-native edits. There is no future run, and the final run should carry BO across.
  • PromotedN3, the three parent sync flows. Today the transfer flow refreshes the 48 parent columns on every run. Once it is deleted, nothing does — a parent rename would leave the copies stale silently and permanently. N3 is the replacement for that maintenance, not an enhancement.
  • KeptThe RevModelDescription fix, and it is now urgent rather than tidy: the final run rewrites that column on ~1,000 rows and the live mapping re-installs the 110-character JSON blob on 979 of them — undoing the R22 repair as its last act.

Four consumers keep pulling through FRM10-12, by design

FRM09, FRM11, FRM13 and BO Manager all read FRM10-12's TableOrders. The viewer is shape-identical, so only the Index row moves; one named owner covers all four and knows to refresh the viewer first. The queries get rebuilt against the four SharePoint lists later.

  • DroppedMy silent-failure objection. It over-weighted the risk of a managed, owned, single-owner procedure with a known refresh order.
  • PathIndex currently resolves to Formulaires/; the viewer goes back to Revue/ at the switch. One row, no M changes.

Blank is a value until FRM10-12 says otherwise

Per column, read out of the workbook rather than one rule applied across all of them — some columns use blank as false, others as a genuine third state.

  • ResultTen marker columns round-trip exactly. Joined across all 1,013 matched units: the boolean agrees with the workbook marker on every row, zero disagreements. Blank is simply false there.
  • ResultThree columns cannot. Frame is a three-value Choice, Engineering Required and LDs are three-state — and the latter two are already flattened at the destination.

CSA is left exactly as it is

“Don't look too far, it's probably just an old unused column. I'll validate that later at the end of the workflow automation, when I've gone through every department.”

  • Backed by0 non-blank on all 1,019 workbook rows and False on all 1,117 list rows. No marker is guessed into the conversion.

Why the list counts run higher on the marker columns. Checked rather than assumed: the excess is entirely the 104 orphan rows that exist on the list but not in the workbook, 92 of which carry True on all four R-columns. They are the archived units X2 marks Delivered. After conversion they will display R — expected for archived units, and worth one glance rather than a fix.

Location also needs inverting — the list stores display names (Extérieur) and FRM11's purge rule tests two-letter codes {XT, TE, FI, LI}. Invert the transfer flow's forward map and round-trip it over every distinct live value. BO Manager needs the same.
