## The one thing that is not running

🔴 **The `Order Items` create-or-update trigger flow is DISABLED.** It was pasted (v002),
enabled, watched, and turned off again when it failed:

    WorkflowOperationParametersRuntimeMissingValue
    'Get_Model' ... 'id' may not be null or empty

`Get_Client` and `Get_Model` read the lookup id straight off the trigger row with no
guard, and **~20 of 1,195 units have no Client, Model or Model Revision** (was recorded
here as 203; corrected 2026-09-14, see the status block above). Editing one
fails the flow, and since `Condition` runs only on `Get_Model [Succeeded]`, the
`Status Date` auto-stamp is skipped with it.

**Consequences while it is off**, both confirmed acceptable with the user:

- no `Status Date` auto-stamp for anyone — staff type the date, as they always have
- `Order Items`' four `_TextField` mirrors go unmaintained — nothing uses them yet

**The fix is designed and written up** in `roadmap.md` under *FIRST daylight job*. Two
parts: guard both gets, and — the real one — decouple the stamp, which needs only
`Step Status` and `Step Status Stamped` and has no business depending on Client or Model.

⚠️ Before re-enabling: re-run the `StepStatusStamped = StepStatus` check (it was 262/262
at 05:55), and **test on a model-less unit, not on a healthy one.** Testing the happy path
is how this reached production.

## Things that will confuse you if nobody says them

- **REST and run-history timestamps in all these notes are UTC, four hours ahead of
  local.** The test log reads 08:35–08:47 for work done at 04:35–04:47.
- **The trigger flow's polling interval is 5 minutes, not the 1 that was pasted.** The
  designer rewrote it on save; the user did not set it and could not find the field. Any
  future paste of that flow reports FORKED on that one key with nobody having caused it.
- **A healthy transfer-flow run reported `Failed`.** That flow is gone now, but the habit
  it taught is still right: verify by reading data, never by run status.
- **`verify_*.py` scripts read the newest export.** After any schema change, re-export
  first or they answer about a list that no longer exists. This bit me once tonight: I
  "re-verified" after a column deletion against an export taken before it.
- **~20 units have no Client, Model or Model Revision** (recorded here as 203; that count
  came from the stale `_TextField` mirrors). They are not broken; their
  Orders genuinely have no model. They are also the reason the trigger flow fails, and
  the reason `Mdl*`/`Rev*` columns are blank on some units.
